# M0 Fragment Mass / Container Fill

## Статус

Утверждённая Visual Specification

## Parent Specification

`Docs/Specifications/Visual/M0_visual_foundation.md`

## Override Parent Specification

Только для данного visual pass переопределяется требование `M0_visual_foundation.md`, согласно которому основная fragment mass должна занимать примерно `50–55%` высоты inner container и располагаться преимущественно в нижней области.

Для `M0_fragment_mass_pass.md` целевой vertical envelope основной fragment mass составляет **от 0% до 85% высоты inner cavity**, считая от внутреннего дна контейнера вверх.

Таким образом, верхняя граница основной fragment mass должна достигать примерно **85% высоты inner cavity**, а оставшиеся верхние \~15% могут сохраняться как свободное пространство.

Все остальные применимые требования `M0_visual_foundation.md` сохраняются без изменений.

Эта Specification определяет отдельный целевой visual pass поверх существующего M0 Visual Foundation.

Все применимые требования `M0_visual_foundation.md` остаются в силе, если данный документ явно не определяет изменение.

---

# Цель

Существенно приблизить воспринимаемую массу фрагментов и характер заполнения контейнера в M0 runtime к утверждённому visual target.

Контейнер больше не должен восприниматься как большой, преимущественно пустой сосуд со свободной кучей отдельных фрагментов на дне.

Он должен восприниматься как плотно заполненная физическая головоломка: значительная масса крупных мягких фрагментов занимает большую часть доступного объёма контейнера, при этом фрагменты визуально подпирают друг друга, соприкасаются, перекрываются и ограничивают движение друг друга.

Основная визуальная цель этого прохода:

**свободная куча отдельных объектов → плотная взаимосвязанная масса фрагментов**

Этот проход относится исключительно к пространственной композиции и воспринимаемой заполненности.

Он не является общим M0 polish pass.

---

# Текущая проблема

В текущем runtime отдельные фрагменты хорошо различимы и уже соответствуют базовому направлению по цвету и мягкости форм, однако их общая композиция существенно отличается от target.

Доминирующие perceptual problems:

### 1. Недостаточное вертикальное заполнение

Масса фрагментов сосредоточена преимущественно в нижней части контейнера.

Над фрагментами остаётся большая непрерывная пустая область.

Из-за этого контейнер воспринимается слишком большим относительно своего содержимого, а композиция не читается как заполненная физическая головоломка.

В target фрагменты присутствуют на большей части полезной высоты контейнера.

---

### 2. Недостаточная плотность

Текущие фрагменты визуально воспринимаются как набор отдельных объектов.

Между многими соседними фрагментами остаются крупные участки видимого фона.

В target фрагменты, напротив, образуют сжатую массу с частыми контактами и очень небольшим количеством крупных пустых пространств.

---

### 3. Слабое ощущение физического контакта

Многие текущие фрагменты выглядят визуально изолированными или лишь слабо соприкасающимися.

Из-за этого композиция не создаёт ощущения, что фрагменты:

- лежат друг на друге;
- давят на соседние фрагменты;
- зажаты между соседями;
- ограничены стенками контейнера;
- образуют непрерывную физическую структуру.

Target в значительной степени строится именно на этих отношениях.

---

### 4. Масштаб фрагментов не создаёт достаточной массы

Хотя отдельные фрагменты в runtime относительно крупные, сочетание их масштаба, количества и расстояний между ними не занимает достаточную визуальную площадь.

В результате композиция воспринимается как небольшая куча внутри значительно более крупного контейнера.

В target используется сочетание крупных и средних фрагментов, суммарные силуэты которых занимают большую часть доступной площади.

---

### 5. Пустое пространство распределено неправильно

В target могут присутствовать локальные отверстия и каналы, но это нерегулярные пространства, сформированные окружающей массой фрагментов.

В текущем runtime присутствуют широкие пассивные пустые области.

Пустое пространство должно стать подчинённым массе фрагментов, а не одним из доминирующих визуальных элементов контейнера.

---

# Обязательные изменения

## 1. Увеличить общую заполненность контейнера

Перекомпоновать фрагменты так, чтобы их масса занимала большую часть полезной площади контейнера.

Композиция должна распространяться значительно выше, чем в текущем runtime.

В верхней области контейнера должны явно присутствовать фрагменты.

Точное расположение не обязано повторять target фрагмент за фрагментом.

Воспринимаемый результат должен воспроизводить характер заполненности и сжатости target.

---

## 2. Увеличить плотность фрагментов

Уменьшить крупные промежутки между соседними фрагментами.

Фрагменты должны часто:

- соприкасаться;
- визуально перекрываться там, где это допустимо текущей моделью rendering;
- располагаться непосредственно друг возле друга;
- образовывать небольшие группы;
- формировать непрерывные цепочки контактов по контейнеру.

Результат не должен напоминать равномерно расставленные UI-объекты или независимые декоративные элементы.

---

## 3. Сформировать непрерывную массу фрагментов

Зритель должен воспринимать фрагменты как одну доминирующую массу, а не как набор изолированных объектов.

По всей композиции должно существовать множество контактных связей.

Масса должна визуально соединяться:

- по горизонтали через контейнер;
- по вертикали через несколько слоёв;
- с левой и правой границами контейнера;
- с нижней областью контейнера.

Необходимо избегать композиций, в которых большинство фрагментов визуально отделено от соседних фоном.

---

## 4. Улучшить вертикальную многослойность

Использовать несколько видимых слоёв фрагментов.

Композиция не должна формировать одну неглубокую горизонтальную кучу.

Фрагменты должны занимать нижнюю, среднюю и верхнюю области полезного пространства контейнера.

Верхняя граница массы фрагментов должна быть нерегулярной, а не образовывать чистую горизонтальную линию.

---

## 5. При необходимости скорректировать относительный масштаб фрагментов

Масштаб фрагментов может быть изменён там, где это необходимо для достижения целевой массы.

Предпочтительна композиция, в которой доминируют крупные и средние фрагменты.

Не следует решать проблему плотности преимущественно за счёт заполнения контейнера большим количеством мелких фрагментов.

Фрагменты должны продолжать восприниматься как значительные по размеру мягкие физические объекты.

Вариативность масштаба должна создавать органичную плотно упакованную композицию, а не равномерную сетку.

---

## 6. При необходимости скорректировать количество фрагментов

Количество фрагментов может быть увеличено, если существующее количество не позволяет добиться достаточной заполненности и плотности.

Количество подчинено визуальному результату.

Не следует увеличивать количество только ради дополнительной детализации.

Каждый дополнительный фрагмент должен непосредственно способствовать:

- заполнению контейнера;
- физическому контакту;
- вариативности силуэтов;
- уменьшению чрезмерного пустого пространства.

---

## 7. Улучшить взаимодействие со стенками

Фрагменты возле левой и правой границ должны визуально взаимодействовать с краями контейнера.

Там, где это уместно композиционно, фрагменты должны выглядеть опирающимися на стенки или ограниченными ими.

Необходимо избегать сохранения равномерного декоративного отступа вокруг всей массы фрагментов.

Масса должна восприниматься как физически ограниченная сосудом.

---

## 8. Сохранить нерегулярное negative space

Цель не заключается в устранении каждого видимого промежутка.

Небольшие и средние нерегулярные пустоты желательны, поскольку помогают сохранять:

- индивидуальные силуэты;
- глубину;
- читаемость;
- ощущение физической упаковки.

Однако negative space должно восприниматься как промежутки **внутри доминирующей массы фрагментов**, а не как крупные пустые области, содержащие разрозненные объекты.

---

## 9. Сохранить читаемость силуэтов

Увеличение плотности не должно превращать фрагменты в нечитаемую многоцветную текстуру.

Отдельные фрагменты должны оставаться различимыми благодаря:

- силуэту;
- цветовым границам;
- overlap/contact;
- локальным промежуткам там, где это необходимо.

Желаемый результат — плотный, но читаемый.

---

# Необходимо сохранить

Следующие элементы должны оставаться неизменными в рамках этого прохода, если только минимальная техническая корректировка не является строго необходимой для размещения фрагментов.

### Контейнер

Сохранить:

- геометрию контейнера;
- размеры контейнера;
- положение контейнера на экране;
- геометрию слива;
- общие пропорции контейнера.

### Rendering контейнера

Сохранить:

- текущее направление glass/material;
- прозрачность;
- существующий подход к rendering контейнера.

Редизайн стекла не относится к этому проходу.

### Background

Сохранить существующий background и общий характер оформления фона экрана.

### UI

Сохранить:

- HUD;
- level label;
- stars;
- back control;
- settings control;
- selector;
- положение и пропорции selector;
- color buttons;
- NEXT element.

### Палитра

Сохранить установленную фундаментальную четырёхцветную палитру:

- red;
- yellow;
- green;
- blue.

Незначительные существующие вариации shading внутри assets фрагментов не являются предметом этого прохода.

### Существующее визуальное направление

Фрагменты должны оставаться:

- мягкими;
- округлыми;
- объёмными;
- toy-like;
- визуально совместимыми с текущим M0 foundation.

Этот проход не должен вводить новый art style фрагментов.

### Gameplay и interaction

Сохранить всё существующее gameplay behavior и input behavior.

Изменения визуальной композиции не должны намеренно переопределять правила игры.

# Вне scope

Следующее явно находится вне scope этого прохода:

- redesign контейнера;
- изменение размера контейнера;
- изменение положения контейнера;
- redesign glass shader;
- glass polish;
- redesign background;
- redesign lighting;
- глобальный redesign rendering;
- новая fragment material system;
- фундаментальные изменения палитры фрагментов;
- redesign selector;
- redesign NEXT;
- redesign HUD;
- изменения typography;
- реализация liquid;
- визуальные изменения liquid;
- foam;
- particles;
- VFX;
- redesign animation;
- изменения input;
- изменения gameplay rules;
- star gameplay;
- win/lose logic;
- level progression;
- общий M0 polish, не связанный с массой фрагментов.

Не использовать этот проход как возможность исправлять несвязанные визуальные проблемы.

Любое несвязанное расхождение, обнаруженное во время реализации, должно быть задокументировано отдельно, а не незаметно включено в этот проход.

# Критерии приёмки

Проход принимается только в том случае, если итоговая runtime-композиция создаёт существенно иное общее визуальное восприятие по сравнению с текущим baseline.

Одной технической корректности недостаточно.

## AC-01 — Доминирующая масса фрагментов

При обычном игровом масштабе просмотра контейнер должен сразу восприниматься как содержащий значительную плотно упакованную массу фрагментов.

Он больше не должен восприниматься преимущественно как пустое пространство контейнера с объектами, расположенными на дне.

---

## AC-02 — Вертикальная заполненность

Фрагменты должны занимать нижнюю, среднюю и верхнюю области полезного пространства контейнера.

Композиция должна распространяться существенно выше текущей runtime-кучи.

Большая непрерывная пустая верхняя половина, сопоставимая с текущим baseline, недопустима.

---

## AC-03 — Плотность

Большинство фрагментов должны иметь визуально значимые отношения контакта или почти контакта с соседними фрагментами.

Крупные участки фона между большинством соседних элементов недопустимы.

---

## AC-04 — Физическая упаковка

Композиция должна создавать убедительное ощущение того, что фрагменты:

- лежат друг на друге;
- давят на соседей;
- зажаты в доступных пространствах;
- взаимодействуют с границами контейнера.

Расположение не должно напоминать вручную расставленный layout иконок.

---

## AC-05 — Непрерывная композиция

Расположение фрагментов должно формировать визуально связанную массу на значительной части контейнера.

Крупные изолированные группы, разделённые широкими пустыми областями, недопустимы.

---

## AC-06 — Нерегулярная многослойность

Положение, размеры, ориентация и контакты фрагментов должны формировать нерегулярную плотно упакованную структуру.

Избегать:

- очевидных рядов;
- grid-like placement;
- повторяющихся расстояний;
- одинаковой ориентации;
- одинакового размера фрагментов.

---

## AC-07 — Иерархия negative space

Пустое пространство может сохраняться, но масса фрагментов должна явно доминировать в композиции.

Крупные непрерывные пустые области не должны быть одним из первых визуальных элементов, воспринимаемых внутри контейнера.

---

## AC-08 — Читаемость фрагментов

Несмотря на увеличение плотности, отдельные силуэты фрагментов должны оставаться читаемыми.

Результат не должен превращаться в неразличимый многоцветный блок.

---

## AC-09 — Сравнение с target direction

При просмотре runtime screenshot рядом с утверждённым target масса фрагментов должна быть perceptually ближе к target, чем предыдущий baseline, по следующим параметрам:

- общая заполненность;
- плотность;
- вертикальное заполнение;
- физический контакт;
- многослойность;
- распределение negative space.

Точное воспроизведение отдельных форм или расположения фрагментов target не требуется.

---

## AC-10 — Сохранение защищённых областей

Не допускается намеренный визуальный redesign следующих элементов:

- container geometry;
- glass/material;
- background;
- selector;
- NEXT;
- HUD;
- fundamental palette.

Любое существенное изменение этих элементов нарушает scope данного прохода, если оно не было отдельно утверждено.

---

## AC-11 — Очевидное улучшение до/после

Side-by-side сравнение:

1. runtime до прохода;
2. runtime после прохода;
3. утверждённого target;

должно демонстрировать очевидное улучшение массы фрагментов без необходимости изучать детали реализации.

Если для того, чтобы заметить улучшение, требуется дополнительное объяснение, результат прохода недостаточен.

---

# QA Evidence

До принятия этого прохода реализация должна предоставить визуальные доказательства.

## Обязательные доказательства

### 1. Runtime screenshot

Предоставить чистый runtime screenshot при обычном целевом gameplay aspect ratio.

Screenshot должен показывать весь релевантный экран, включая контейнер целиком.

Editor Scene view недостаточен.

---

### 2. Трёхстороннее сравнение

При QA review необходимо сравнить:

- предыдущий M0 runtime baseline;
- новый runtime после этого прохода;
- утверждённый target reference.

Основная область review — композиция фрагментов внутри контейнера.

---

### 3. Visual review checklist

QA должен явно оценить:

- заполненность контейнера;
- вертикальное заполнение;
- плотность фрагментов;
- контакты между фрагментами;
- взаимодействие со стенками;
- вариативность размеров;
- вариативность силуэтов;
- распределение negative space;
- читаемость фрагментов;
- сохранение элементов вне scope.

---

### 4. Runtime verification

Подтвердить, что визуальная композиция присутствует в реальном runtime, а не только воспроизведена в editor-only setup или mockup.

---

## Полномочия по приёмке

Этот проход требует Visual & UX review.

Успешная compilation, корректный запуск runtime или отсутствие Unity errors не являются визуальной приёмкой.

Если реализация технически работает, но итоговая масса фрагментов всё ещё существенно отличается от утверждённого target по заполненности, плотности или физической упаковке, проход остаётся незавершённым.
